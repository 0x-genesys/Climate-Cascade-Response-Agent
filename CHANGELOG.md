## Prompt-Only ++Baseline++ Findings

- **Run:** `baseline-6f97a217-d44a-4aac-a478-0e14d253057f`, `gpt-5-mini-2025-08-07`.
- **Method:** one deep prompt only. The model had no incident dossier, AOI facts, source retrieval, RAG, maps, tools, retries, verifier, or deterministic analysis.
- **Result:** LSAC@5 `0/17` (`0%`). All four requirements were uncovered because the proposals were generic and location-unspecified.
- **Safety:** `0` unsafe autonomous-action findings, `0` missing evidence references, and `5` valid prompt-context citations.
- **Evidence:** `runs/baseline/nepal-emsr927-v2-prompt-only.run.json`, `.adjudication.json`, and `.evaluation.json`.
- **Decision:** use this as the intended simple-prompt baseline. Retain the old curated-dossier baseline only as historical work, not the comparison headline.



## ++Iteration 1++ Final Findings

This is the final retained Iteration 1 proof-of-concept record, not a scored improvement experiment.

- **Run and source:** live CEMS `EMSR927`, `run-66147235-554b-4c98-88a1-45d56b8f4014`, evaluated against the frozen Nepal rubric only as a diagnostic transfer.
- **Model and scope:** one `gpt-5-mini-2025-08-07` response-supervisor call, four unapproved drafts, live source verification, immutable evidence, deterministic reference and safety checks, and no deterministic impact tools.
- **Automatic result:** `0` unsafe autonomous-action findings, `0` missing evidence references, and `4` valid evidence references.
- **Manual coverage:** a project-owner, AI-assisted review marked Bharatpur covered and Timure, Bidur, and Syapru Besi uncovered: LSAC@5 `3/17` (`17.65%`).
- **Why it is not comparable:** the frozen baseline and live run used different CEMS snapshots, and the reviewer was not a credentialed emergency manager.
- **Observed limitation:** current CEMS AOI status makes Timure, Bidur, and Syapru Besi visible, but provides no route condition, built-up impact, or critical-facility content for a precise protective action.
- **Decision:** retain the workflow, safety checks, and live evidence model; revise the capability path. Iteration 2 must deterministically parse and validate CEMS product contents before a same-input benchmark.
- **Evidence:** `runs/iteration_1/nepal-emsr927-live-poc.`* and `docs/execution/2026-08-31-15-iteration-1-live-poc-finalization.md`.



## ++Iteration 2++ Final Findings

This is a live CEMS product-statistics proof of concept, not a fair baseline comparison.

- **Retained run:** `run-f7fd675d-6370-4470-ac51-cc1356b7f581`, CEMS `EMSR927`, response-supervisor configuration `4`, and `gpt-5-mini-2025-08-07`.

## ++Iteration 3++ Final Findings

This is a live CEMS product-statistics proof of concept, not a fair baseline comparison.

- **Retained run:** `run-04c58215-d4ec-4dda-aba9-eb87b62ad6ec`, live CEMS `EMSR927`, response-supervisor configuration `4`, and provider-returned model `gpt-5-mini-2025-08-07`.
- **Change:** An independent deterministic evidence-and-safety supervisor reviews the typed action draft after model output and before the review queue. It sees no provider reasoning or response-supervisor prompt. Unknown citations and autonomous language reject; a named, unaddressed CEMS data gap requests revision. There are at most two revisions, then a visible blocked outcome.
- **Automatic result:** The initial draft passed the independent verifier with `0` findings. The existing final checks also found `0` unsafe autonomous patterns, `0` missing evidence references, and `5` valid references. The run reached `awaiting_human_review` with five draft-only actions.

Bharatpur remained a limitation only, not a concrete evidence-request proposal, so its `3` points remain uncovered.

With the original response prompt restored, the supervisor allocated its five actions across all three completed AOIs and covered the three high-weight protective needs. The verifier did not require revision in this run; this validates its independent pass gate, not its revision path.

- **Why not comparable:** The run used mutable live CEMS data and a project-owner rubric transfer, while the baseline is a prompt-only frozen-task test. Treat this as diagnostic evidence only.
- **Decision:** Keep the independent verifier and fail-closed revision boundary. Before claiming a measured planning uplift, freeze a product-level benchmark and evaluate more than one live run; do not tune location choices against hidden gold actions.

## ++Iteration 4++ Final Findings

This is a live CEMS product-statistics proof of concept, not a fair baseline comparison.

- **Retained run:** `run-6f20b6fd-1100-43de-8cf6-e5a041fe9653`, live CEMS `EMSR927`, `gpt-5-mini-2025-08-07`.
- **Lifecycle change:** each action can receive a versioned, durable qualified-human decision with reviewer ID, role, rationale, assumptions, timestamp, and an ordered audit event. The latest decision is now rendered on the matching review-queue card, replacing the stale `Draft only` label.
- **Dashboard change:** the dashboard starts named live examples for Nepal, South-west Poland, and Sri Lanka rather than a pinned practice case. It also explains the difference between a CEMS coverage status and a geographic map, places deterministic impact facts after the human queue, and gives the review form a readable, responsive layout.
- **Automatic and manual result:** the retained live transfer run reached `awaiting_human_review`, with `0` unsafe autonomous-action findings, `0` missing evidence references, and LSAC@5 `13/17` (`76.47%`): Timure `5/5`, Bidur `5/5`, Syapru continuity `0/4`, Bharatpur evidence request `3/3`.
- **Why the score did not change:** Iteration 4 runs after the response supervisor has already selected the five drafts. It improves traceable human control and safe abstention, not upstream action selection. The dashboard refinement changes neither the evidence package nor the selected actions.
