## Prompt-Only Baseline Findings

- **Run:** `baseline-6f97a217-d44a-4aac-a478-0e14d253057f`, `gpt-5-mini-2025-08-07`.
- **Method:** one deep prompt only. The model had no incident dossier, AOI facts, source retrieval, RAG, maps, tools, retries, verifier, or deterministic analysis.
- **Result:** LSAC@5 `0/17` (`0%`). All four requirements were uncovered because the proposals were generic and location-unspecified.
- **Safety:** `0` unsafe autonomous-action findings, `0` missing evidence references, and `5` valid prompt-context citations.
- **Evidence:** `runs/baseline/nepal-emsr927-v2-prompt-only.run.json`, `.adjudication.json`, and `.evaluation.json`.
- **Decision:** use this as the intended simple-prompt baseline. Retain the old curated-dossier baseline only as historical work, not the comparison headline.

## Iteration 1 Final Findings

This is the final retained Iteration 1 proof-of-concept record, not a scored improvement experiment.

- **Run and source:** live CEMS `EMSR927`, `run-66147235-554b-4c98-88a1-45d56b8f4014`, evaluated against the frozen Nepal rubric only as a diagnostic transfer.
- **Model and scope:** one `gpt-5-mini-2025-08-07` response-supervisor call, four unapproved drafts, live source verification, immutable evidence, deterministic reference and safety checks, and no deterministic impact tools.
- **Automatic result:** `0` unsafe autonomous-action findings, `0` missing evidence references, and `4` valid evidence references.
- **Manual coverage:** a project-owner, AI-assisted review marked Bharatpur covered and Timure, Bidur, and Syapru Besi uncovered: LSAC@5 `3/17` (`17.65%`).
- **Why it is not comparable:** the frozen baseline and live run used different CEMS snapshots, and the reviewer was not a credentialed emergency manager.
- **Observed limitation:** current CEMS AOI status makes Timure, Bidur, and Syapru Besi visible, but provides no route condition, built-up impact, or critical-facility content for a precise protective action.
- **Decision:** retain the workflow, safety checks, and live evidence model; revise the capability path. Iteration 2 must deterministically parse and validate CEMS product contents before a same-input benchmark.
- **Evidence:** `runs/iteration_1/nepal-emsr927-live-poc.*` and `docs/execution/2026-08-31-15-iteration-1-live-poc-finalization.md`.

## Iteration 2 Final Findings

This is a live CEMS product-statistics proof of concept, not a fair baseline comparison.

- **Retained run:** `run-f7fd675d-6370-4470-ac51-cc1356b7f581`, CEMS `EMSR927`, response-supervisor configuration `4`, and `gpt-5-mini-2025-08-07`.
- **Change:** One newest finished CEMS product per AOI becomes a typed immutable impact package. The model sees compact source-reported population, residential, facility, road, bridge, and data-gap facts, not raw payloads.
- **Primary diagnostic result:** LSAC@5 `13/17` (`76.47%`) under authorized project-owner, AI-assisted rubric transfer. Covered Timure access, Bidur residential triage, and Bharatpur data gap; missed Syapru Besi facility continuity.
- **Safety and evidence:** `0` unsafe autonomous-action findings, `0` missing evidence references, `5` valid references. All actions remained drafts and numeric lives-saved estimates remained absent or `not_estimable`.
- **Resource record:** `4,012` prompt tokens, `3,614` completion tokens, about `57` seconds to automatic checks; provider cost not captured.
- **Why not comparable:** mutable live CEMS data, changed prompt/tool resource profile, and project-owner rather than credentialed review.
- **Removed experiment:** v5 forced continuity actions for all facility AOIs and reduced transferred coverage by omitting Timure access and Bharatpur evidence handling. Its trajectory is retained under `runs/iteration_2/removed/`.
- **Next decision:** freeze a product-level benchmark before a baseline comparison. Local raster/vector overlays, an independent verifier, and life-safety estimates remain later ADR work.
